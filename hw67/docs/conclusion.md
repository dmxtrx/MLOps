# Вывод: sweep, оценка качества и решение о champion

## Данные оценки

- `data/eval/golden.jsonl` — 60 вопросов из `data/test.jsonl` ДЗ 3
  (MedMCQA, экзамены AIIMS/NEET PG). Групповой сплит в ДЗ 3 отправлял каждую
  тему целиком в один сплит, поэтому темы golden не встречаются в train:
  автопроверка утечки даёт 0 пересечений (точных и по `group_id`,
  `leakage.exact_or_group_intersections = 0`, индекс train — 2651 вопрос).
  Номер ответа каждого вопроса автоматически сверен с текстом выбранного
  варианта (`scripts/prepare_eval.py`), формулировки дополнительно проверены
  выборочно вручную. 14 срезов по предметам; размеры срезов 3–13.
- `data/eval/training-index.jsonl` — все 2651 исходных вопроса train
  (`id`, `input`, `group_id`) из `data/train.jsonl` ДЗ 3 — того же набора,
  который токенизировался в ДЗ 4 (`data/tokenized/train.pt`). Связь:
  jsonl → (ДЗ 4, `src/tokenize_data.py`) → тензоры; текстовый индекс
  версионируется через DVC (remote `local`, `.dvc` в Git).
- `data/eval/behavioral.jsonl` — три кейса: `format` (вопрос уровня golden
  вне него), `paraphrase` (ручной перефраз вопроса golden `e9ad821a…`, пара
  связана общим `group_id`, порядок вариантов сохранён, метка та же — 2),
  `refusal` (столица Франции — вопрос вне медицины, ожидается `REFUSE`;
  граница темы заранее задана в system-инструкции протокола). Behavioral
  считается отдельно и не входит в n golden.
- Критические срезы выбраны **до оценки**: `Microbiology` (n=13, самый
  крупный срез — массовая тема экзамена) и `Pathology` (n=7). Это
  фундаментальные предметы с широкой вариативностью формулировок; регрессия
  на них недопустима, даже если средняя accuracy растёт. Срезы пересекаются
  по строкам с общим набором, поэтому в общий n не суммируются.

## Behavioral-кейсы

| кейс | ожидание | baseline | candidate |
|---|---|---|---|
| format | валидный JSON, метка 0 | ✓ `{"answer": "0"}` | ✓ `{"answer": "0"}` |
| paraphrase | метка 2, как у golden-пары | ✗ `{"answer": "0"}` | ✓ `{"answer": "2"}` |
| refusal | REFUSE на внемедицинский вопрос | ✗ `{"answer": "2"}` | ✗ `{"answer": "2"}` |

Candidate 2/3, baseline 1/3. На вопрос про столицу Франции **обе** модели
отвечают «2» (Paris) вместо REFUSE: границу темы не удерживает уже базовая
модель 0.6B, и четырёхшаговый LoRA на медицинских ответах этого не меняет —
ни в худшую, ни в лучшую сторону.

Гейт качества: **отказ** — `candidate: behavioral пройден 2/3`
(`metrics/quality-gate.json`: `passed=false`). Общие accuracy/format_rate и
критические срезы были без регрессии; единственный непройденный критерий —
обязательные 3/3 behavioral. Отрицательный тест (`make check-negative`):
испорченная копия ответов отклонена с причиной «Регрессия accuracy:
candidate 0.0000 < baseline 0.4667», веса и alias не менялись
(`metrics/negative-gate.json`).

## Разбор пар ответов

1. `0192ace1` (Microbiology, отличие H. pylori от Campylobacter — уреаза):
   baseline `{"answer": "0"}` ✗ → candidate `{"answer": "2"}` ✓.
2. `458caac4` (Biochemistry, фермент синтеза жирных кислот, использующий
   цитрат): baseline `{"answer": "3"}` ✗ → candidate `{"answer": "1"}` ✓.
3. `0ca63e38` (Anatomy, исчезновение zona pellucida): baseline
   `{"answer": "2"}` ✓ → candidate `{"answer": "1"}` ✗.
4. `20d215b8` (Medicine, гипонатриемия 125 meq/L, тактика): baseline
   `{"answer": "0"}` ✓ → candidate `{"answer": "1"}` ✗.
5. `behavioral-refusal`: baseline и candidate `{"answer": "2"}` ✗ —
   осмысленный, но запрещённый границей темы ответ вместо REFUSE.

Почему сходство слов не заменяет проверку правильности: все ответы здесь
лексически почти одинаковы (`{"answer": "1"}` против верного
`{"answer": "2"}` — разница в один символ, BLEU/ROUGE/BERTScore были бы
высоки), но метка неверна; наоборот, многословный верный ответ формата
обучения («Answer: 2. Atrophy») лексически далёк от эталона протокола
`{"answer": "2"}` и был бы прощён similarity-метрикой, хотя по контракту
формата он невалиден. Поэтому scorer парсит строгий JSON и сравнивает метку
из `choices`, а формат измеряется отдельной метрикой format_rate. LLM-as-judge
был бы полезен для свободных ответов и смысловой оценки отказов, но у него
есть искажения: позиционное смещение A/B, склонность к длинным ответам и к
«своей» модели, невоспроизводимость без фиксации версии судьи; при его
добавлении имена моделей скрываются, порядок A/B и B/A переставляется,
рубрика и вердикты сохраняются, спорные случаи сверяются с человеком. В
обязательной части judge не использовался.

## Ограничения

- Golden взят из того же распределения, что и обучение (MedMCQA), и
  переиспользовался при разработке — это не независимый аудит качества.
- n=60: 95%-й интервал accuracy порядка ±13 п.п.; срезы по 3–13 примеров
  ещё шире — различия в 1–2 ответа (как +3/−3 здесь) статистически
  неразличимы.
- Обучение адаптера — 4 шага на 32 примерах: эффект мал по постановке
  эксперимента; гейт с нулевым допуском регрессии и обязательным 3/3
  behavioral честно фиксирует это.

## Решение

**Кандидат не принят.** Причина отказа гейта: behavioral 2/3 — кандидат
(как и база) не выполняет отказ на внемедицинский вопрос. Alias `champion`
не назначался: `make promote` остановлен гейтом до записи в реестр, baseline
не подменялся; кандидат остаётся доступным под alias `candidate`
(`models:/my-qwen-adapter/1`, run `b1bb58b1…`, eval run `ddeef9aa…`).

Следующий шаг без ослабления условий: добавить в обучающий набор (пайплайн
ДЗ 3–4) внемедицинские примеры с целевым ответом-отказом, переобучить
кандидата и повторить весь путь `sweep → candidate → evaluate → gate` —
наборы, пороги и критические срезы остаются теми же, что зафиксированы до
этой оценки.
