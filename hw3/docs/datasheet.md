# Datasheet: MedMCQA-SFT

Датасет для ДЗ 3 курса MLOPS-26: английские медицинские вопросы с четырьмя
вариантами ответа в chat-формате, для дообучения Qwen3.

## 1. Назначение

Модель учится выбирать единственный верный вариант и отвечать его номером и
текстом, без объяснений. Задача — выбор ответа, а не генерация рассуждения.

## 2. Источник

- **Набор:** MedMCQA — https://huggingface.co/datasets/openlifescienceai/medmcqa
- **Что это, по карточке набора:** вопросы индийских медицинских вступительных
  экзаменов AIIMS и NEET PG. Train собран из пробных и онлайн-тестов,
  validation — вопросы NEET PG. Размеры: 182 822 / 4 183 / 6 150 строк в
  train / validation / test; 21 предмет, около 2,4 тысячи тем.
- **Что используется:** train и validation. Test не используется.
- **Лицензия:** Apache-2.0, указана в карточке набора. Права на исходные
  экзаменационные вопросы карточка отдельно не оговаривает.
- **Хранение:** parquet-файлы источника под DVC (`dvc add sources/medmcqa`),
  в git — только `sources/medmcqa.dvc`.

## 3. Переработка источника (стадия `collect`)

Набор не перекладывается в JSONL один в один. Каждый шаг виден числом в
`metrics/collect.json`:

| | train (v1 и v2) | validation (только v2) |
|---|--:|--:|
| просмотрено строк | 9 160 | 4 183 |
| отброшено: `choice_type = multi` | −3 155 | −1 367 |
| отброшено: нет темы | −3 005 | −2 497 |
| отброшено: битая разметка | 0 | 0 |
| **записано** | **3 000** | **319** |

Train просматривается до тех пор, пока фильтры не пропустят `n_rows = 3000`
строк, поэтому числа по train относятся к первым 9 160 строкам файла, а не ко
всему сплиту. Validation просмотрен целиком.

Что делает каждый шаг:

1. **Только `single`.** Формат ответа — один номер и один текст, и он
   гарантированно соответствует разметке только для одноответных вопросов.
2. **Только вопросы с темой.** Тема — ключ группы для сплита; строке без неё
   честно попасть некуда.
3. **Сверка разметки.** Индекс верного ответа `cop` лежит в 0..3, все четыре
   варианта непустые. Проверяется структура, а не медицинская правильность
   ключа.
4. **Разведение инструкции.** Пять формулировок системного промпта; вариант
   выбирается детерминированно по sha1 от id примера, так что `raw.jsonl`
   воспроизводим от запуска к запуску.
5. **Группа = предмет + тема** (`"Anatomy / …"`): одноимённые темы разных
   предметов не склеиваются в одну группу.

## 4. Формат

JSONL, один пример на строку:

```json
{"id": "<id из MedMCQA>", "topic": "<Subject> / <Topic>",
 "messages": [
   {"role": "system", "content": "<одна из пяти формулировок инструкции>"},
   {"role": "user", "content": "Subject: …\nTopic: …\n\nQuestion:\n…\n\nOptions:\n0. …\n1. …\n2. …\n3. …"},
   {"role": "assistant", "content": "Answer: <N>. <текст варианта N>"}]}
```

Схема проверяется в стадии `clean` через pydantic: роли строго в порядке
system → user → assistant, пустых полей нет. Битая строка роняет стадию с
номером строки в сообщении.

## 8. Как устроен сплит

- **Групповой:** ключ — нормализованная тема (`предмет / тема`). Тема целиком
  уходит в один сплит.
- **Доли:** 80 / 10 / 10 по строкам, `seed = 42`. Группы перемешиваются, затем
  каждая отправляется в сплит, которому больше всего недостаёт до своей доли.
- **Дедупликация до сплита:** точная по нормализованному тексту вопроса и
  near-dup через MinHash (шингл 4 слова, 64 перестановки, Жаккар ≥ 0.85).
  Порог совпадает с порогом проверки контаминации.
- **Контаминация:** 0 на всех четырёх уровнях — id, текст, группы, near-dup.
  Ненулевое значение роняет стадию `split`.
- **Групп в сплитах:** **[ЗАПОЛНИТЬ: groups из metrics/split.json]**.

## 10. Чего датасет не покрывает

- **Язык и контекст.** Только английский; вопросы индийских экзаменов —
  названия препаратов, дозировки и клинические рекомендации могут
  расходиться с практикой других стран.
- **Только одноответные вопросы.** Вопросы `multi` — около трети
  просмотренных строк train (3 155 из 9 160) — отброшены.
- **Смещение к размеченным темам.** Без темы оказалась половина одноответных
  вопросов train (3 005 из 6 005) и 89 % в validation (2 497 из 2 816).
  Вопросы без темы в датасет не попадают, поэтому реальные вопросы NEET PG
  представлены всего 319 строками.
- **Не случайная выборка.** v1 — первые подходящие строки train в порядке
  файла. Все 21 предмет покрыты, крупнейший — Anatomy, 311 из 3000
  (10.4 %), но равномерность по предметам гейтом не проверяется.
- **Без объяснений.** Поле `exp` не используется: модель учится отвечать без
  рассуждения.
- **Правильность ключа не проверялась.** Сверка разметки структурная; верность
  самого ответа — на совести источника.
- **Вопросы по изображениям не отфильтрованы.** Сколько их в наборе — не
  подтверждено.
- **ПДн.** Стадия чистки выполнена (**[ЗАПОЛНИТЬ: pii_rows_masked]**
  срабатываний), но шаблоны телефона и даты рождения рассчитаны на русский
  текст (+7/8, «дата рождения»). На английском источнике эффективно работает
  только поиск email.
- **Утечка в оценку.** v2 содержит validation MedMCQA. Если модель потом
  оценивать на MedMCQA, dev-сплит для этого не годится — он в обучении.

## 11. Как воспроизвести

```bash
uv sync
uv run dvc pull
make v1
make v2
make check
```

`dvc pull` работает с локальным remote автора. Без него источник скачивается
заново с Hugging Face в `sources/medmcqa` (из Китая — через
`HF_ENDPOINT=https://hf-mirror.com`), после чего `make v1` / `make v2`
пересобирают всё остальное.
